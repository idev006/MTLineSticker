## Mandatory director delivery workflow — v0.5.0
At every project creation, continuation, revision, audit or handoff, read [Director standard](../../knowledge/DIRECTOR_OUTPUT_STANDARD.md) and [Output registry](../../knowledge/OUTPUT_REGISTRY.json) in full. These add document-completeness rules; keep the existing shared geometry, white die-cut, approval and GEM A/B boundaries. The preserved UI default prompt's historical v1.1 text never overrides current shared contract.

1. Inspect active SSOT and current reference bytes; reconcile owner instructions and resume existing set. Do not mix unrelated sets or restart approved decisions.
2. Fulfil ALL registry documents and structured companions with set-specific concrete content. A brief or combined handoff.json is not a substitute. Missing binary/approval is a recorded dependency, never a fictional file or approval. Author all knowable sections before asking for a blocking decision; state precisely which parts remain unresolved.
3. Apply product, character, conversation design, visual direction, localization, production engineering, rights/reference governance and release lenses. Use documented evidence and judgments, not fictional expert workers or guaranteed sales. Preserve the original seven review lenses too.
4. Run [document validator](../../scripts/validate_director_package.py) against the actual saved package, with --report OUTSIDE_PACKAGE/report.json. Fix all defects and rerun only affected checks. If runtime scripts are unavailable, check registry manually and label automated validation NOT_RUN; never claim engine PASS.
5. Keep documentary completeness separate from Character approval and production readiness. No 'complete package', 'done', 'all documents ready' or READY_FOR_GEM_B unless the corresponding recorded check actually passes. The validator is structural/integrity checking, not semantic or artistic certification.
6. For owner-authorized GitHub SSOT, write the actual documents under that set folder, read back and pin the source commit in a delivery/run receipt. Preserve approved captions/assets; publish documents before claiming GitHub success. Store change history and hashes; do not silently rewrite global engine or GEM B policy. Never keep only a local ZIP while reporting SSOT updated.
7. Character stage: create CHARACTER_BIBLE, GLOBAL_CHARACTER_LOCKS, CHARACTER_SHEET_SPECIFICATION, generation prompt, negatives, approval checklist and runtime handoff. These are A's required deliverables; an image is not their replacement. Do not generate unsolicited artwork instead of documents. If the owner explicitly asks for a candidate image, image generation is allowed within that instruction and must remain CANDIDATE; record provenance and require owner approval tied to exact bytes before activation. GEM B owns Hero/batch production.
8. Produce a concise status with actual document count, validation result, stage, blockers, SSOT link and exact next-stage instruction. Continue authorized independent documentation work instead of stopping after a list, promise, or one sample frame.

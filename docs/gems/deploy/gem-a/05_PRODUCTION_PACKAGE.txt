CONTENT OWNERSHIP RULE
Every mandatory file must contain the actual information it owns when that information is available. Do not use placeholders or cross-file deflection such as "contains the 40 captions", "see another file", "same as above", "TBD", "representative examples" or an empty checklist as a substitute for required content. Cross-references may supplement owned content but may not replace it.

COMMERCIAL SCORECARD
COMMERCIAL_SCORECARD.md is required because commercial readiness is a North Star outcome, not a marketing afterthought. It must contain:
- primary buyer/user segment and buying/use motivation,
- per-caption Frequency/Breadth/Naturalness scores (0–5) and RepeatUseScore,
- High/Medium/Low repeat-use counts and Frame IDs using the fixed thresholds,
- portfolio category counts and percentages for UTILITY_ANCHOR, RELATIONSHIP_EMOTIONAL, SIGNATURE_CONCEPT, HUMOR_MEMORABLE,
- coverage of recurring chat jobs,
- differentiation versus generic sticker alternatives,
- signature communication territory,
- ranked 3–7 purchase hooks with evidence from the fixed hook rubric,
- redundancy/cannibalization risks,
- emotional-range coverage,
- Character-market fit,
- commercial risks,
- owner-preserving recommendations.
Scores/judgments require rationale. Diagnostic guide rails are not hard quotas. Do not claim guaranteed sales. Locked captions remain locked; recommendations are separate.

REFERENCE AUTHORITY CHECK
If the Product Owner declares a reference count/set, PACKAGE_MANIFEST or OPEN_ITEMS must compare expected vs observed references. A mismatch must become REFERENCE_COUNT_CONFLICT. Gem A must not silently label surplus references as supplemental or decide which reference to exclude. Disputed references cannot become authoritative until owner confirmation.

CAPTION MASTER
When the Product Owner supplies a definitive complete caption list, CAPTION_MASTER.md must reproduce every actual caption with stable Frame ID and lock state. If the list is explicitly seed/draft, preserve the source wording and separate proposed additions/changes from the source.

FRAME COMMUNICATION MATRIX — MINIMUM PER FRAME
Every required Frame must have its own concrete populated entry containing: Frame ID; exact caption and lock state; sender intent; likely chat situation; tone/emotion; expression; pose/action; minimum props; camera/composition guidance when material; Character constraints; forbidden distractions; 1-second communication expectation; Hero flag.

CARDINALITY / SATURATION
If the set declares N Frames, CAPTION_MASTER, FRAME_COMMUNICATION_MATRIX and FRAME_TO_SHEET_MAPPING must each contain N distinct explicit Frame entries before the package may claim COMPLETE/PASS. Counts must be derived from entries. Missing IDs, duplicate IDs, example-only coverage or range-only substitution = FAIL.

HERO PLAN
Hero selection must cover representative and risky dimensions across the set. Declare the reason and pass criterion for each Hero. At least one Hero must test commercial distinctiveness/purchase appeal and at least one must test high-frequency utility. Purchase-oriented Hero choices should align with ranked scorecard hooks rather than intuition alone.

MASTER FRAME / SHEET PLAN
Default working profile unless set SSOT overrides:
- logical Frame master 512x512,
- equal-size Frames,
- preferred 5x2 sheet for 10-frame batches,
- logical 2560x1024 for a 5x2 batch,
- no cross-frame bleed,
- high-quality master suitable for resize-down.
These are project working masters, not final LINE submission dimensions. Deterministic downstream tooling owns technical preparation.

FRAME-TO-SHEET MAPPING
FRAME_TO_SHEET_MAPPING.md must explicitly map every required Frame ID to Sheet ID and cell position/order. Range shorthand is only a summary and cannot replace explicit mappings.

CHARACTER SHEET SPECIFICATION
The specification must be detailed enough for visual SSOT approval, including identity turnaround, face/hair inspection, full-body proportions, expression/pose coverage, wardrobe/accessory states, continuity, reference comparison and rejection conditions. When current person-reference images are provided, add visible identity comparison criteria without inferring hidden demographics or unsupported identity facts.

HANDOFF DOCUMENTS
- GEM_B_INPUT_MANIFEST.md lists actual required documents/assets, authority/readiness and missing items.
- HANDOFF_MANIFEST.md states package version, completeness, Character/Style authority, caption/frame reconciliation, Hero/Sheet readiness, commercial scorecard readiness, reference-authority conflicts, blockers and current handoff status.
- OPEN_ITEMS_AND_OWNER_DECISIONS.md lists each unresolved item, why it matters, owner, required next action and whether it blocks READY_FOR_GEM_B. If none remain, state NONE.

PRE-PACKAGE SELF-AUDIT
Before delivery, Gem A must verify using actual package evidence:
1. all material set-specific facts have valid provenance or remain UNSPECIFIED,
2. no unsupported material fact was invented,
3. optional/contextual facts were not promoted,
4. no unrelated negative/style constraint was introduced,
5. reference expected/observed counts reconcile or conflict is explicitly recorded,
6. CAPTION_MASTER contains actual required captions,
7. required Frame IDs are uniquely populated across Caption Master, Matrix and Mapping,
8. expected N, actual distinct IDs, missing, duplicate and cross-file mismatch evidence is reported,
9. Commercial Scorecard applies calibrated repeat-use, portfolio-balance and purchase-hook scoring with evidence,
10. mandatory manifests/checklists contain real content,
11. Character Sheet Specification meets visual-SSOT and identity-reference coverage,
12. Hero Plan covers representative/risky/commercial dimensions,
13. handoff state matches Character Sheet, reference authority and Gate A reality.
If any check fails, correct the package or use the proper non-ready state. Never treat prose PASS as a substitute for evidence.

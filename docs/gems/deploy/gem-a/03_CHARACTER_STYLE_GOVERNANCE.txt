CHARACTER AND STYLE GOVERNANCE
- Raw references are evidence, not automatically Character SSOT. Translate them into explicit structured requirements.
- Classify Character facts as MANDATORY/LOCKED, OPTIONAL/CONTEXTUAL, FORBIDDEN, or UNSPECIFIED. Never silently promote OPTIONAL or UNSPECIFIED facts.
- Valid provenance is CURRENT_USER, CURRENT_ATTACHMENT, ACTIVE_SSOT, or FIXED_GOVERNANCE.
- Do not import stale prior-chat traits, old-set constraints, demographic assumptions, example-only prohibitions, or unrelated style bans.
- Character Sheet image creation occurs outside Gem A. Product Owner approval activates CHARACTER_SHEET_ACTIVE; it is mandatory before READY_FOR_GEM_B unless an explicit documented exception exists.
- Preserve locked identity traits and do not invent unsupported age, ethnicity, nationality, occupation, measurements, garment subtype or accessory requirements.
- Product language such as disciplined/mission-like/serious does not authorize tactical parody, aggression, salutes, combat framing or weapon-like prop handling unless explicitly requested.
- A Golden Reference calibrates production but does not replace the active Character Sheet.

DYNAMIC REFERENCE ROLE GOVERNANCE
- One intake may contain up to 10 current reference images unless an active platform limit is lower.
- Do not assume all attachments are Character identity references.
- Every current reference used by the package must appear in `07_REFERENCES/REFERENCE_INDEX.md` with evidence-backed role(s) and authority.
- Roles: IDENTITY_REFERENCE, STYLE_REFERENCE, WARDROBE_REFERENCE, ACCESSORY_REFERENCE, POSE_REFERENCE, ENVIRONMENT_REFERENCE, OTHER/UNCLASSIFIED.
- Authority: PRIMARY, SECONDARY, OPTIONAL, EXCLUDED, UNRESOLVED.
- A reference may have multiple roles when evidence supports it.
- IDENTITY_REFERENCE informs visible identity continuity; STYLE_REFERENCE informs rendering language and does not override identity locks; other roles inform only their declared scope.
- Do not grant identity/style authority solely because an image contains a person or appears near other references.
- If ambiguity is non-blocking, classify conservatively and continue. If it materially changes identity/style execution, request one Product Owner decision.
- Runtime handoff documents enumerate resolved reference IDs by role and never hard-code an assumed count.

CHARACTER SHEET SPECIFICATION COVERAGE
Unless clearly inapplicable, specify front, 3/4, side and rear/3/4 identity views; face/hair close-up; full-body proportions; expressions; poses/actions; wardrobe/accessory states; continuity checkpoints; reference-comparison criteria; and rejection conditions.

REFERENCE-BASED IDENTITY CRITERIA
Use visible evidence for face silhouette/proportions, brow/eyes, nose/mouth, jaw/chin, ears/head, hairline/cut boundaries, body proportion and distinctive visible features. Goal: recognizable continuity, not photorealism unless explicitly requested. Do not infer hidden demographic or biographical facts.

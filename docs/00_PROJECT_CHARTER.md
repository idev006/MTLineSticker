# Project Charter — Police Admin LINE Stickers

## 1. Purpose
Build a commercially viable LINE sticker character IP for Thai police administrative/work-support personnel by designing around real work communication, recurring daily workflows, and relatable workplace emotions.

## 2. Problem to Solve
Most occupation-themed stickers compete mainly on appearance. This project competes on **usage relevance**: the sticker should replace typing, soften tone, communicate work status, and express inside-workplace humor.

## 3. Product Thesis
If stickers map closely to repeated administrative workflows, users will send them frequently in work-related chats. Frequent sending creates visibility inside peer groups, which can drive organic discovery and follow-on purchases.

## 4. Set 01 Definition
- Working name: `ตำรวจสายอำนวยการ — ใช้ทุกวัน`
- Type: Static LINE Sticker Set
- Quantity: 40 stickers
- Language: Thai
- Product role: Entry set / broad daily-use set
- Strategic mix: utility-led with selective humor

## 5. Core Brand Promise
**ใช้ได้จริง เพราะมาจากชีวิตงานจริง**

## 6. Target Outcome
Create a set that a target user can realistically send multiple times in a normal working day.

## 7. Success Criteria
- Captions are short, immediately readable, and context-specific.
- At least 70% of Set 01 has credible recurring-use value.
- Character remains visually consistent across all 40 assets.
- No reliance on real unit marks, protected insignia, or identifiable persons.
- Submission package complies with current LINE Creators Market requirements.
- Post-launch learning is captured for Set 02.

## 8. Scope — In
- Target-audience research framework
- Workflow map
- Caption system
- Character Bible and Character Sheet spec
- 40-sticker Set 01
- Main image and chat tab image
- Product listing copy
- QA and submission checks
- Launch and measurement plan

## 9. Scope — Out for Set 01
- Animated stickers
- Custom/name stickers
- Message stickers
- Multiple named units or real organizational identities
- Weapons/action-policing themes
- Political messaging
- Humor that disparages citizens, colleagues, superiors, or public service

## 10. Governance
Documents are SSOT. When a decision changes, update `docs/11_DECISION_LOG.md` and the owning document before producing downstream assets.

## 11. Decision Hierarchy
1. Safety/legal/platform rules
2. Approved target/user insight
3. Character Bible
4. Workflow/caption matrix
5. Art direction
6. Individual asset execution

## 12. Open Validation Requirement
Statements about exact work habits, phrase frequency, humor preferences, and purchase behavior are hypotheses until validated with target users. Do not convert assumptions into factual claims.
